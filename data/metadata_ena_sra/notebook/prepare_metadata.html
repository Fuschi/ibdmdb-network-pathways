Preparation of IBDMDB sequencing metadata

Integration of ENA and NCBI SRA run-level metadata for metagenomic network and pathway analyses

1 Aim of the notebook

This notebook prepares the sequencing metadata used for the analysis of the Inflammatory Bowel Disease Multi’omics Database (IBDMDB) dataset.

The main goal is to build a clean and consistent run-level metadata table by integrating information retrieved from two complementary public resources:

  1. the ENA read-run file report for BioProject PRJNA398089;
  2. the NCBI SRA Run Selector table for the same BioProject.

The resulting table will be used to select the subset of samples relevant for the downstream metagenomic analyses, with particular focus on shotgun metagenomic data suitable for microbial community, network, and pathway-based analyses.

2 Data sources

The starting metadata files are:

  • filereport_read_run_PRJNA398089.tsv, downloaded from the ENA Portal API;
  • SraRunTable_PRJNA398089.csv, downloaded from the NCBI SRA Run Selector.

Both files describe sequencing runs associated with the IBDMDB/iHMP study, but they contain partially overlapping and partially complementary information. For this reason, they are first standardized and compared, and then joined into a single metadata table.

3 General workflow

The notebook follows these steps:

  1. load the ENA and SRA metadata tables;
  2. standardize column names from the SRA table;
  3. harmonize key identifiers and technical fields across the two sources;
  4. check consistency of run accessions and shared columns;
  5. merge ENA and SRA metadata into a single table;
  6. clean selected clinical and technical variables;
  7. filter the metadata to retain the samples suitable for the downstream metagenomic analysis.

3.2 Join ENA and SRA metadata

The ENA and SRA tables are joined using the run accession and the main shared technical identifiers.

metadata_join <- report_ena %>%

5 Standardize disease labels

Disease labels are harmonized to obtain a consistent set of values across the metadata table.

The original metadata contain different representations of the same condition, such as abbreviations and full names. These values are converted to compact snake-case labels that are easier to use in downstream analyses.

metadata_join <- metadata_join %>% 
  mutate(
    host_disease = if_else(is.na(host_disease), "missing", host_disease),
    host_disease = str_to_lower(host_disease),
    host_disease = case_when(
      host_disease %in% c("cd", "crohn''s disease", "crohn's disease", "crohn’s disease") ~ "crohns_disease",
      host_disease %in% c("uc", "ulcerative colitis") ~ "ulcerative_colitis",
      host_disease %in% c("nonibd", "non-ibd") ~ "control",
      TRUE ~ host_disease
    ))

6 Select shotgun metagenomic sequencing runs

The full metadata table contains multiple assay types, including shotgun metagenomic, metatranscriptomic, viral metagenomic, and amplicon sequencing data.

For the main downstream analysis, only shotgun metagenomic runs from human gut metagenome samples are retained.

Before filtering, the available combinations of library strategy, scientific name, library selection, and library source are summarized.

6.1 Inspect missing disease labels at subject level

Disease status should be consistent within each subject. Therefore, subjects with multiple disease labels are inspected.

In particular, this step checks whether any subject has both a missing disease label and a non-control disease label. Such cases require manual inspection before assigning missing values to the control group.

metadata_join_filt %>%
  group_by(host_subject_id, host_disease) %>%
  count() %>%
  ungroup() %>%
  group_by(host_subject_id) %>%
  filter(n() > 1) %>%
  arrange(host_subject_id) %>%
  group_by(host_subject_id) %>%
  filter(
    any(host_disease == "missing"),
    !any(host_disease == "control"))

6.2 Build the final metadata table

The final metadata table is generated by applying a set of inclusion criteria for the downstream analysis.

The filtering steps are:

  1. remove the subject/run combination with ambiguous missing disease annotation;
  2. retain adult subjects only;
  3. convert the remaining missing disease annotations to control;
  4. retain subjects with at least 10 metagenomic sequencing runs.

The last criterion is useful for longitudinal or repeated-measure analyses, where subjects with too few observations may not provide enough information to reconstruct the correlation network.

metadata_join_final <- metadata_join_filt %>%
  filter(!(host_subject_id == 4004 & host_disease == "missing")) %>%
  filter(host_age >= 18) %>%
  mutate(host_disease = if_else(host_disease == "missing", "control", host_disease)) %>%
  group_by(host_subject_id) %>%
  filter(n() >= 10) %>%
  ungroup() 
metadata_join_final %>%
  summarise(
    n_runs = n(),
    n_subjects = n_distinct(host_subject_id),
    .by = host_disease
  ) %>%
  arrange(desc(n_runs))
